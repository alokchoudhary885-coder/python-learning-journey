# Constructors in Python OOP (`__init__`)

## 1. Definition
A **constructor** is a special method inside a class that Python calls **automatically** whenever a new object (instance) is created from that class. In Python, the constructor is always named `__init__` (short for initialization).

Its primary job is to initialize the object's instance variables (state) when memory is allocated.

---

## 2. Why We Use Constructors
Without a constructor, you would have to manually assign attributes to each object one by one after creating it:
```python
# Inefficient manual way:
emp = Employee()
emp.name = "Alok"
emp.salary = 50000
```
With a constructor:
- Initial state is guaranteed immediately at object creation time.
- Prevents missing or uninitialized attributes.
- Makes code clean, concise, and reproducible.

---

## 3. Syntax
```python
class ClassName:
    def __init__(self, param1, param2):
        self.param1 = param1
        self.param2 = param2
```
- `__init__` begins and ends with double underscores (called a *dunder* or magic method).
- `self` must be the first parameter in `__init__`. It refers to the specific instance being created.

---

## 4. How It Works Internally
When you write `emp = Employee("Alok", 21)`:
1. Python first calls `__new__()` to allocate memory for the new object.
2. Python immediately passes this newly created instance to `__init__(self, "Alok", 21)` as the `self` argument.
3. The instance attributes (`self.name = "Alok"`) are stored in the object's personal namespace dictionary (`emp.__dict__`).
4. The initialized object reference is returned and assigned to the variable `emp`.

---

## 5. Types of Constructors in Python

| Constructor Type | Description | Example |
| :--- | :--- | :--- |
| **Default Constructor** | Generated by Python automatically if you don't write `__init__`. Takes no arguments other than `self`. | `class Car: pass`<br>`c = Car()` |
| **Non-Parameterized Constructor** | Has `__init__(self)` but takes no user arguments; sets hardcoded default values. | `def __init__(self): self.name = "Guest"` |
| **Parameterized Constructor** | Takes custom arguments passed during object creation. | `def __init__(self, name, age): self.name = name` |
| **Default-Valued Constructor** | Parameters have fallback values if caller omits them. | `def __init__(self, name, role="Student"): ...` |

---

## 6. Practical Example
```python
class Employee:
    def __init__(self, emp_id, name, city, salary=25000):
        self.emp_id = emp_id
        self.name = name
        self.city = city
        self.salary = salary

    def get_details(self):
        return f"[{self.emp_id}] {self.name} from {self.city} - Rs. {self.salary}"

emp1 = Employee("E101", "Alok", "Jaipur", 45000)
emp2 = Employee("E102", "Ayush", "Ratlam")

print(emp1.get_details())
print(emp2.get_details())
```

### Expected Output:
```text
[E101] Alok from Jaipur - Rs. 45000
[E102] Ayush from Ratlam - Rs. 25000
```

---

## 7. Understanding the `self` Parameter
- `self` is not a Python keyword; it is a strong coding convention. (Technically you could name it anything, but PEP 8 strictly mandates using `self`).
- When you call `obj.display()`, Python converts it internally to `ClassName.display(obj)`.
- `id(self)` inside the constructor is exactly equal to `id(obj)` outside.

---

## 8. Common Mistakes
1. **Returning a value from `__init__`:**
   ```python
   # ❌ SyntaxError / TypeError: __init__() should return None, not 'str'
   def __init__(self, name):
       return "Hello"
   ```
   `__init__` must always return `None`.
2. **Spelling `__init__` with single underscores:**
   `def _init_(self):` is treated as a normal method, not a constructor!
3. **Forgetting `self` as the first argument:**
   `def __init__(name, age):` fails with `TypeError: __init__() takes 2 positional arguments but 3 were given`.

---

## 9. Quick Revision Notes
- Constructor runs **automatically** on instance creation.
- Python does not support multiple `__init__` methods in the same class (method overloading); the last defined `__init__` overwrites earlier ones.
- Use default parameter values (`param=default`) to achieve flexible constructor behavior.
- Every instance receives its own unique attributes via `self`.

---

## 10. Practice Questions & Answers

### Q1: Can a class have two `__init__` methods in Python?
**Answer:** No. Unlike Java or C++, Python does not support constructor overloading by having multiple `__init__` definitions. The second `__init__` definition will completely overwrite the first one. To accept different sets of arguments, use default values (`arg=None`) or `*args` / `**kwargs`.

### Q2: What happens if you do not define any `__init__` method in a class?
**Answer:** Python automatically provides a default empty constructor that takes only `self` and performs no custom initialization.

### Q3: Why does `__init__` always return `None`?
**Answer:** Because object creation is handled by `__new__()`. The job of `__init__` is solely to mutate/initialize the instance in place, not to produce or replace the object reference.

### Q4: Write a `Book` class constructor taking `title`, `author`, and optional `pages=100`.
```python
class Book:
    def __init__(self, title, author, pages=100):
        self.title = title
        self.author = author
        self.pages = pages
```

### Q5: How can you inspect all attributes set by a constructor on an object?
**Answer:** You can access the object's `__dict__` dictionary attribute:
```python
b = Book("Python 101", "Alok")
print(b.__dict__)
# Output: {'title': 'Python 101', 'author': 'Alok', 'pages': 100}
```
